# R182b — ME r182b_frontend_para_rango

## Resumen

Cierre de la deuda pre-existente H-R182a-1 (1 failed + 9 errors en
`tests/syquex/test_concurrency.py` y `tests/syquex/test_traductor.py`,
presente desde c2cd52e): el frontend Syquex (`build/syq_frontend.exe`)
segfaulteaba (0xC0000005 → `SYQ_JSON_ERROR=-3` o JSON truncado) al compilar
un `.syq` con bucles `para` de rango: `para i en 0..n:` (índef) y
`para i = a .. b [paso p]:`.

## Causa raíz

El emisor JSON (`syquex/syq_json.syn`) reconstruye el span slot1 de cada
nodo como `ptr64 = (hi[i] << 32) | ptr_str[i]`, con `hi` desde `trad_hi()`,
copia de `sq_tokens_hi()` que hace `trad_copiar_payload`
(`syquex/traductor.syn`). Los 5 literales sintéticos del desugar de `para`
fijaban `ptr_str`/`len_str` pero NO escribían `sq_tokens_hi[n]`:

| Nodo | Literal | Sitio original |
|---|---|---|
| `miembro` (`__init__`) | `_SQ_INIT` | parser.syn 668 |
| `paso_r` (paso 1 en-rango) | `_SQ_ONE_R` | parser.syn 999 |
| `expr_paso` (paso 1 clásico) | `_SQ_ONE` | parser.syn 1024 |
| `lt` (`<`) | `_LT` | parser.syn 1050 |
| `incr_val` (`+`) | `_PL` | parser.syn 1053 |

La reconstrucción leía `hi[i]` heredado (basura de otro token) → dirección
inválida → segfault en `sj_byte_en` al leer el payload.

## Lecciones

- Los literales sintéticos con puntero estático DURANTE el parseo deben
  escribir AMBOS carriers: `ptr_str` (bajo) y `sq_tokens_hi` (alto) — el
  emisor JSON reconstruye punteros 64-bit a partir del par.
- El patrón de referencia ya existía (`_SQ_SELF` L768) — buscar el patrón
  canónico del mismo archivo antes de replicar el bug.
- Bisección por stash (sugerida en R182a) no fue necesaria: la lectura del
  emisor+desugar bastó para aislar la causa raíz una vez descartado que
  `canal <- i` fuera el desencadenante (era incidental: el test lo usa dentro
  de un `para`).
