DETALLE TÉCNICO:
  1. **H-R88-1 (@export lang, syquex/parser.syn:165-171):** el parser consumía
     el identificador `lang` (p.ej. "python") via `sq_id(est)` pero no lo
     copiaba al nodo NODO_EXPORT. La llamada `sq_copiar_nombre(est, n, lang)`
     copia `ptr_str`/`len_str`/bits-altos del nodo identificador al NODO_EXPORT;
     `trad_copiar_payload` del traductor (L222-228) propaga esto a SemNodo.
     Verificado: `trad_texto(i)` retorna "python"/"typescript".
  2. **H-R87-2 (externo estructura/constante, syquex/parser.syn:131-155):**
     - `externo estructura Vec3` → NODO_EXTERNO con `ptr_str="Vec3"`,
       `valor_int=1` (marker estructura).
     - `externo constante SALUDO = "hola"` → NODO_EXTERNO con `ptr_str="SALUDO"`,
       `hijo_der=CADENA_LIT("hola")`, `valor_int=2` (marker constante).
     - El traductor maneja NODO_EXTERNO genéricamente (L641-662): copia payload
       y traduce hijos. El parser mantiene la forma `externo funcion` intacta.
  3. **H-R86-1 (dedup str_eq, syquex/lexer.syn:136-145):** el `str_eq` local
     del lexer Syquex se conserva (comentario H-R86-1 en L136-140); el harness
     de R89 no incluye `nucleo/lexer.syn`, por lo que no hay duplicación. El
     dedup en unity build completo (`_seen_sym` en pipeline.py) queda como
     mejora futura para builds unity con todos los módulos.

  - (i) El `externo estructura Vec3` se parsea sin `:`/campos (gramática M3 §3
    L88 requiere `:`). Para FFI, solo el nombre es necesario; el parser no
    consume `:` — si se usa `externo estructura Vec3:` con `:`, el `:` quedaría
    sin consumir y causaría error. Registro de límite conocido.
  - (ii) H-R87-1 sigue pendiente (decision del Arquitecto sobre keyword
    `variable` vs `let`).
