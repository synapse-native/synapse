## Objetivo

Explorer/Architect deterministas sobre el grafo canónico, Coder/Reviewer/Fixer
con LLM real (servidor falso en el oráculo), 2-3 inferencias y código final
validado con el compilador actual (`--check --no-emit`).

- `opensyn/pipeline_multiagente.syn`: imports canónicos
  (`nucleo.grafo_conocimiento`, `opensyn.validation_loop`), estructuras reales
  del grafo, fases deterministas locales (`explorar_contexto`,

  `_syn_ollama_consultar` con overrides de host/puerto/modelo, límite de 3
  inferencias y validación final con `validar_con_check`.

  `opensyn/pipeline_multiagente.syn` (trinquete de Fase 32).
- `docs/plan_ME_r207_pipeline_multiagente.md`,

## Desviaciones

- El codegen actual no soporta structs anidados: `ContextoPipeline` aplana las
  métricas de impacto y `analizar_impacto_completo` retorna `MetricasImpacto`
  (solo escalares). Las listas `NodoAfectado`/`ContratoCritico`/`Ciclo` se usan
  localmente para calcular los conteos. Limitación de codegen para r217.
- `explorer_det.syn`/`architect_det.syn` siguen en el baseline de r210/r211; el
  pipeline implementa las fases mínimas localmente. Deuda de integración r217.
- `validation_loop_corregir` hace una corrección LLM tras `validar_con_check`,
  no el bucle completo de 3 intentos, para respetar el límite del pipeline.

## Lecciones

- El emisor C no soporta campos struct anidados: los emite como puntero y el
  constructor compound-literal falla. Aplanar a escalares es la salida segura.
- Importar `std.texto` y `nucleo.grafo_conocimiento` juntos expone la colisión
  `a_texto`; el grafo debe usar su conversor `_json_a_texto`.
- `_syn_ollama_consultar` ya está exportado por `validation_loop`; redeclararlo
  en el pipeline produce “Redefinición”.
- El oráculo E2E debe usar el compilador actual (`python main.py`), no el
  `synapse.exe` instalado, que puede estar stale.
