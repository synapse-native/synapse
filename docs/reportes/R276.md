## Qué faltaba

La matriz `release_matrix.yml` ya construía, firmaba (Ed25519) y verificaba las
firmas de lo publicado, y `distribuir.py --requerir-firma` falla sin clave. Lo
que **no existía** era una comprobación de que el artefacto distribuido
*funcione*: nadie ejecutaba `synapse --version` sobre el binario del release, ni
compilaba y ejecutaba un programa con él, ni verificaba que el bundle completo
(binario, `install.sh`, `synapse.iss`, SBOM, attestation, manifiesto y firmas)
estuviera íntegro. Un release podía publicarse con un binario roto.

## Entrega

### `scripts/verificar_release_limpio.py` (nuevo, `cumple Manual 9 §6.1/§6.3/§2.4/§2.5`)

Gate por plataforma sobre un directorio de distribución:

1. **Artefactos obligatorios**: binario, `MANIFEST.sha256` (+`.sig`),
   `synapse.pub`, `install.sh`, `synapse.iss`, `synapse.spdx.json`,
   `synapse.attestation.json`. Falta uno → `FAIL` con la lista.
2. **Integridad SHA-256**: recalcula cada archivo del manifiesto y cada sidecar
   `.sha256`; detecta archivos listados pero ausentes y artefactos firmados
   fuera del manifiesto.
3. **Firmas Ed25519**: `.sig` válida con `synapse.pub` para **cada** artefacto
   del manifiesto y para el manifiesto mismo (verificación offline, sin red).
4. **Smoke real**: `synapse --version`, compilación y ejecución de un programa
   (`Hola Mundo`) con el binario distribuido, y `opensyn --version` si el
   agente viaja en el mismo directorio. El smoke compila con cwd en la raíz del
   proyecto (el layout de este bundle); en una plataforma foránea se declara
   `no-ejecutable` y el gate sigue exigiendo integridad y firmas.
5. `--json` escribe la evidencia (plataforma, contadores, hashes, pasos).

Salida: `PASS: release limpio <plataforma> — N artefactos, M firmas Ed25519, smoke: OK` (rc 0)
o `FAIL: ...` (rc 1).

### `.github/workflows/release_matrix.yml`

Job nuevo `smoke_release_limpio` con matriz de cuatro runners
(`ubuntu-latest`, `ubuntu-24.04-arm`, `macos-latest`, `windows-latest`): descarga
el artefacto de su plataforma, ejecuta el gate con smoke y sube
`docs/reportes/release_<plataforma>.json` como `smoke-<plataforma>`.
`create_release` pasa a `needs: [release_matrix, smoke_release_limpio]`: **un
release no se publica si el smoke de una plataforma falla**.

### `tests/auditoria/test_r276_release_limpio.py` (nuevo, 5 tests)

Bundles sintéticos con claves Ed25519 reales: el gate pasa con un bundle
íntegro, y **falla** con un byte manipulado, con una firma ausente y con un
directorio vacío; el quinto test exige que el workflow cablee el gate en las
cuatro plataformas y que `create_release` dependa de él.

## Límites declarados (H-R276-2)

- **VM Windows limpia**: no medida en esta sesión. El gate local corre sobre el
  bundle del repo; la prueba de instalador sobre VM sigue abierta.
- **Linux/macOS/ARM**: no medidos localmente. La matriz queda cableada y su
  evidencia es el artefacto `smoke-<plataforma>` del run de CI; hasta que ese run
  exista, esas plataformas no están certificadas.
- El smoke compila con cwd en la raíz del proyecto porque este bundle no es un
  árbol instalado (`{app}/bin` + `{app}/std`), que es lo que cubren los
  instaladores y sus jobs.

  (H-R276-1); no hay colisión de ids.
