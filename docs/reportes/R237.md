# R237 — El instalador de Windows empaqueta el toolchain C (cierra H-R234-2)

**ME:** r237_instalador_toolchain · **Manual:** 9 §2.5 / §7 / §2.2 · **Cierra:** H-R234-2 (ALTO)

## Problema

R236 hizo que `synapse.exe` buscara el compilador C por sí mismo, pero el
instalador no entregaba ninguno: `scripts/install.ps1` sólo comprobaba el `gcc`
del PATH y avisaba «instale MinGW manualmente». En una VM limpia el usuario
seguía sin poder compilar.

## Cambio

- **`instaladores/windows/empaquetar_toolchain.py`** (nuevo): stagea el subset
  mínimo de MinGW desde `toolchain_gcc12/mingw64` en
  `instaladores/windows/dist/toolchain_gcc12/mingw64` — **3836 archivos, 300 MB**
  frente a los 936 MB del toolchain completo. Copia `gcc`, `as`, `ld`, `dlltool`,
  `cc1`, `collect2`, `liblto_plugin`, las DLLs del compilador (también junto a
  `cc1`, ver abajo), `x86_64-w64-mingw32/{include,lib}` y `lib/gcc`. `--verificar`
  compila y ejecuta un C con `PATH` = `bin` staged + `System32`.
- **`instaladores/windows/synapse.iss`**: componente `toolchain` (Types: full
  minimal) y `[Files]` de `dist\toolchain_gcc12\mingw64\*` a
  `{app}\toolchain_gcc12\mingw64` — exactamente el directorio que el resolver de
  `nucleo/principal.syn` busca desde `{app}\bin` (`..\toolchain_gcc12\mingw64\bin`).
  `skipifsourcedoesntexist` mantiene el `.iss` compilable sin staging.
- **`instaladores/windows/scripts/install.ps1`**: verifica el toolchain incluido
  (`gcc --version` sobre `{app}\toolchain_gcc12\mingw64\bin\gcc.exe`) y sólo cae al
  `gcc` del PATH (o al aviso manual) si el componente no se instaló.
- **`.gitignore`**: `instaladores/windows/dist/` (el staging es artefacto de build).

### Hallazgo durante la implementación

`cc1.exe` vive en `libexec/gcc/<triple>/<version>/` y Windows busca las DLLs
primero en el directorio del ejecutable: con las DLLs sólo en `bin/`, `cc1`
moría con `0xC0000135` (DLL no encontrada) y `gcc` devolvía rc=1 sin mensaje.
Las DLLs del compilador se copian, por tanto, también junto a `cc1.exe`.

## Límites

- No se compiló el setup con `lzma2` real (el tiempo excede una sesión
  interactiva); el pipeline de release debe ejecutar
  `empaquetar_toolchain.py` antes de `iscc`.
- La VM Windows realmente limpia del criterio Manual 9 §7 sigue pendiente: aquí
  la instalación se hizo en el host con el `PATH` recortado a mano (paso 2 de R234).
