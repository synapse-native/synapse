## 2. Hallazgos y causas raíz

### Finding H-R90-8b: Funciones locales definidas no exportadas por runtime S1
**Problema:** El runtime S1 (`build/syq_frontend.exe`) filtra funciones locales definidas cuando el `.syq` no contiene `funcion principal` (`nucleo/principal.syn:709`). Esto hacía que `dividir` (definida localmente en el fixture) no apareciera en el plano JSON → `tipo_de_expr` no resolvía su tipo.
**Fix:** Injectar `funcion principal() -> nulo: retornar` en el source físico ANTES del runtime S1 (`pipeline.py:533-540`).

### Finding H-R90-11: tipo_de_expr no resolvía funciones definidas localmente
**Problema:** `tipo_de_expr` (`emit_expressions.py:143`) solo resolvía `_BUILTINS` y `_func_return_types`, no funciones definidas por el usuario localmente.
**Fix:** Lookup en `ctx._funciones_usuario` (registro en H-R90-13):
```python
if nombre in ctx._funciones_usuario:
    return ctx._funciones_usuario[nombre].tipo_retorno
```

### Finding H-R90-15: dividir builtin con tipo Resultado
**Problema:** `dividir` era un stub `double dividir(double,double)` en `generator.py:1187` → `ExprPropagar` (`?`) no infería el tipo `Resultado<decimal,texto>`, fallaba la propagación.
**Fix:**
- Registrar `dividir` en `_BUILTINS` (`context.py:129`) con tipo `'Resultado<decimal, texto>'`
- Registrar en `_FUNCIONES_BUILTIN` (`semantic_scope.py:58`) con params `['decimal','decimal']` y retorno `'Resultado<decimal, texto>'`
- Stub `_prescan_dividir` (`generator.py:1471`) detecta uso y emite stub condicional con typedef `Resultado_decimal_texto`

### Finding H-R90-13: Parámetros con valores por defecto en builtins
**Problema:** `abrir(ruta, modo="r")` requería 2 args; los tests de FFI llamaban con 1.
**Fix:** `_builtin_defaults` en `GeneratorContext.__init__` + `_BUILTIN_PARAMS_DEFAULT` en `semantic_scope.py` para rellenar args omitidos.

### Finding ME-R90-9: SentenciaRecuperar dual-mode
**Problema:** `recuperar` (catch clause) necesitaba dual-mode AST + puente + codegen + checker.
**Fix:** Implementado `SentenciaRecuperar` en `ast_nodes.py`, `puente_canonico.py`, `emit_declarations.py`, `semantic_checker.py`, `generator.py` (header + body mode tracking via `ctx._modo`).

### Finding ME-R90-10: ExprRecibirCanal unboxing
**Problema:** `recibir canal` no hacía unboxing del ADT `Resultado`.
**Fix:** `ExprRecibirCanal` en codegen unboxea `.ok`/`.err` según tag de `Resultado_T`.
