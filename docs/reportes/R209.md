## Objetivo

Dejar `opensyn/router.syn` y `opensyn/chat.syn` compilables y verificables E2E:
el router clasifica tareas, extrae bloques de código y parsea diagnósticos del
compilador; el chat selecciona modelo desde `config.toml`, construye contexto
del workspace, extrae y valida el bloque generado.

  `atoi_f`; `let` en variables locales; `ejecutar_lint`/`ejecutar_fmt` retornan
  `entero`; extracción de bloques con `extraer_codigo_router`; truncado seguro
  del prompt con `subcadena`; preservación de `contexto_texto`/`tipo_nodo` con
  `_syn_strcpy`; orden de `planificar_antes_de_actuar` corregido para evitar

## Lecciones

- El parser Synapse rechaza `[]`, `intentar` y `para cada`; `chat.syn` debe
  usar constructores `Lista<texto>()`, `para ... en` y `romper`/`siguiente`.
- `prompt.datos` puede ser memoria de solo lectura; para truncar se reasigna
  con `subcadena(prompt, 0, max_chars)`.
- Los parámetros `texto` se consumen en las fronteras; si el llamador conserva
  la cadena, debe pasar `_syn_strcpy`.
- `leer_archivo` está restringido al cwd; para rutas del perfil se usa
  `_syn_leer_archivo`.
- Un stub local determinista es preferible a enlazar una API declarada sin
  implementación C, siempre que la desviación quede registrada.
