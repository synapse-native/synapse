HALLAZGO R113 (causa raíz, verificado en el C generado):
  El generador S1 LIBERA los parámetros CadenaSegura de una función cuando un
  `retornar` ocurre dentro de un bloque anidado (si/mientras, depth>=1) —
  `_syn_texto_liberar(param)` antes del return (y en varios retornos de nivel
  raíz). Un helper .syn que retorna desde un bloque anidado CONSUME la cadena
  viva del llamador (use-after-free silencioso sobre el pool). Síntoma real:
  la lista de modelos del chat se veía como "(1)" con basura `\0r:6.7b` y los
  comandos /modelos y /model fallaban tras el primer uso.
  Fix en dos capas:
  1. pipeline.py Paso 2b: fix_borrowing ahora se aplica a TODOS los módulos C
     generados en dir_base (opensyn/syquex), no solo a nucleo/_texto.c — los
     wrappers read-only (strlen_s/strstr_f/strchr_f/…) de los binarios opensyn
     liberaban sus argumentos y corrompían cadenas vivas.
  2. opensyn/principal.syn: helpers reescritos single-pass (un solo recorrido,
     solo primitivas inline seguras: subcadena copia, strlen_s, strchr_f,
     str_eq, atoi_f) SIN retornos en bloques anidados; el llamador pasa copias
     frescas (strcpy_f) de las cadenas vivas (modelos/prompt) para que el
     consumidor nunca toque el buffer maestro.
