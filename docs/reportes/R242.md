# R242 — `synapse opensyn` en el binario nativo

**ME:** `r242_native_opensyn_cli` · **Fecha:** 2026-11-17 ·
**Commit:** `616e321` · **Rama:** `release/v8.1.0-industrial` ·
**Manuales:** Manual 8 §4.1, §4.2 · **Evidencia:** `auditoria/evidencia/4437bc919e048bd1.json`.

## Problema

El CLI Python (`cli.py`, desde R149) expone `synapse opensyn <subcomando>`, pero
el **binario nativo** que se distribuye en `{app}\bin` no lo conocía:

```
$ dist/bin/synapse.exe opensyn status
[Synapse] Compilando archivo: opensyn...
Error de compilacion
```

`principal()` trataba `argv(1)` como archivo fuente, así que el producto
instalado por el setup de R237 (sin Python) no exponía OpenSyn en absoluto.
Era el criterio de cierre 6 del PLAN MAESTRO INDUSTRIAL.

## Solución

`nucleo/principal.syn` gana la rama `opensyn` en el dispatcher de subcomandos,
antes del prescan de flags y de `generar_etapa()`:

| Invocación | Resultado | rc |
|---|---|---|
| `synapse opensyn` / `--help` | Lista los 5 subcomandos | 0 |
| `synapse opensyn status` | Delegado en `opensyn.exe status` (estado real) | 0 |
| `synapse opensyn doctor` | Delegado en `opensyn.exe doctor` | 0/1 |
| `synapse opensyn download\|finetune` | Error honesto: requiere servidor local `:8088` | 1 |
| `synapse opensyn bindings\|transpile` | Error honesto: requieren el toolchain Python de `opensyn/` | 1 |
| `synapse opensyn <otro>` | «Subcomando OpenSyn desconocido» + uso | 1 |

Decisiones de diseño:

- **Delegación en `opensyn.exe`** para `status`/`doctor`: el diagnóstico local
  ya está implementado y probado en el binario OpenSyn nativo (Manual 7 §2.1).
  Duplicarlo en C habría creado dos fuentes de verdad que divergen.
- **Errores honestos** en vez de éxito ficticio donde la capacidad depende de
  Python (mismo patrón que `cli.py` con `download`/`finetune`).
- **Ruta del compañero** resuelta desde `argv(0)` (mismo directorio), de modo
  que funciona invocado como `dist/bin/synapse.exe`, `{app}\bin\synapse.exe` o
  con ruta relativa; si `opensyn.exe` no está, falla con mensaje claro.
- `--help` global y el uso sin argumentos listan también `opensyn <sub>`
  (Manual 8 §4.1: el CLI unificado es el punto de entrada de todo el ecosistema).
