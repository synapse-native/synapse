## Alcance

1. **H-canon-LET (bug de producción, `compilador/canonical.py`):** el nodo
   `DeclaracionVariable` tiene campo Python `tipo` (anotación de tipo del `let`)
   que al serializar machacaba la llave discriminante `"tipo"` del JSON canónico
   (quedaba `""` o `entero`): el round-trip `.syn.json` (`ast_a_canonico` →
   `canonico_a_ast`) perdía el tipo de nodo y corrompía el pipeline lógico.
   **Fix:** la anotación viaja como `tipo_annot` (`_CAMPOS_RENOMBRAR` +
   deserializador) en paridad con el AST nativo (`nucleo/ast_nodes.syn:83`,
   campo `tipo_param`) — Manual 2 §13 (el ejemplo completo define el
   discriminante como NOMBRE DE NODO en cada nodo).
2. **6 asserts M2 §13** (D2/D6/F1/F1c/F1_4): alineados al formato canónico plano
   (`data["tipo"] == "Programa"`, su wrapper `synapse == "2.0"` deprecado por 175d268).
3. **2 asserts débil (Manual 4 §4.2)** en `test_codegen_embebido_d_f1d.py`: del
   placeholder ABI `void* = nulo` (F1.2d, 9264fbc) al runtime real Fase 23
   (`WeakRef ref = ((WeakRef){0});`, ME-F23-7 795ce6f) — **autorización
   Arquitecto regla 5** concedida en sesión (Opción A).
4. **1 aserción de cuerpo `@export`**: verificada por el retorno real del
   Lifetime Scope (`int64_t r = (a + b);` + `return _ret_;`).
5. **mapa_alineacion.md**: entrada puntual para `compilador/canonical.py`
   que señala la sección "Manual 2 §13" del manual (el fallback legacy
   `compilador/* → Manual 1` no tiene sección puntual y el gate exigía
   `Manual 1 §(manual entero)`).
