# R100 — Fix atoi_f use-after-free + LSP hover/completion/definition reales

**Fecha:** 2026-08-27
**Fase:** 27 — Herramientas de Desarrollo
**ME:** ME-F27-L2
**Commit:** `73f13ac`
**Autor:** Buffy (agente)

---

## 1. Problema

El servidor LSP nativo (`nucleo/lsp_v3.syn`) tenía múltiples bugs críticos que impedían el funcionamiento:

1. **`atoi_f()` use-after-free**: la función libera su argumento (`_syn_texto_liberar`) ANTES de parsearlo con `_syn_atoi`. Esto causa que el ID de las respuestas JSON-RPC sea siempre 0 o basura.

2. **`_json_a_texto()` buffer estático**: cada llamada sobreescribe `_ser_buf`. Si se llama dos veces seguidas (para method y params), el primer resultado se pierde.

3. **`desde_texto(body)` libera body**: la RAII de Synapse libera el parámetro al salir de la función, invalidando el body para uso posterior.

4. **`lsp_doc_get()` puntero a buffer estático**: retornaba un puntero a `_G_lsp_doc_buf`. La RAII de Synapse intentaba liberarlo → heap corruption.

5. **Windows stdout text mode**: `\n` se convertía a `\r\n`, duplicando el `\r` en headers LSP (`\r\r\n\r\r\n` en vez de `\r\n\r\n`).

---

## 2. Soluciones implementadas

### 2.1. `extraer_entero()` — reemplazo seguro de `atoi_f`

Parser manual de enteros que NO libera su argumento. Usa solo `subcadena`, `cmp_texto` y aritmética.

### 2.2. Extracción inline de ID desde body crudo

En vez de pasar `body` como parámetro a una función (que lo liberaría via RAII), el ID se extrae inline en el `while` principal usando solo builtins (`strstr_f`, `subcadena`, `strlen_s`).

### 2.3. Externo functions para almacenamiento de documento

- `lsp_doc_store(texto)` — copia el texto a un buffer estático C
- `lsp_doc_get()` — retorna un **malloc copy** del buffer (no puntero estático)
- `lsp_doc_clear()` — limpia el buffer

Esto evita que la RAII de Synapse libere memoria estática.

### 2.4. `_setmode(stdout, O_BINARY)` en Windows

En `runtime/core/io.c`, se llama `_setmode(_fileno(stdout), _O_BINARY)` la primera vez que se escribe. Esto evita que Windows traduzca `\n` a `\r\n` en modo texto.

### 2.5. Eliminación del handler `initialized`

El `escribir_linea("")` escribía un `\n` al stdout, contaminando el stream LSP. Se eliminó porque `initialized` es una notificación que no requiere respuesta.

## 3. Hallazgos críticos de Synapse RAII

| # | Hallazgo | Impacto |
|---|----------|---------|
| H1 | `atoi_f()` libera argumento antes de parsear | ID de respuestas siempre 0 |
| H2 | `_json_a_texto()` usa buffer estático `_ser_buf` | Cada llamada sobreescribe anterior |
| H3 | `desde_texto(body)` libera body vía RAII | Body queda inválido después |
| H4 | `obtener_campo()` libera nodo vía RAII | Doble free en llamadas encadenadas |
| H5 | `lsp_doc_get()` retornaba puntero a buffer estático | RAII lo liberaba → heap corruption |
| H6 | Windows stdout text mode duplica `\r` | Headers LSP corruptos |
| H7 | Funciones con parámetros `texto` los liberan al salir | No pasar variables cross-scope |

**Regla aprendida:** Nunca pasar variables `texto` como parámetro a funciones Synapse si necesitas usarlas después. Extraer valores inline con builtins antes de que la RAII los destruya.
