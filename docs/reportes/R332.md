## Objetivo

Desbloquear el build modular de `opensyn/principal.syn` en CI y el smoke de
release en Linux/macOS, sin tocar los tests.

## Hallazgos

- `_modelo.c` llamaba `longitud(CadenaSegura)` sin prototipo; el gcc nuevo de
  CI lo trata como error (`implicit declaration`). El header modular declaraba
  `longitud` para colecciones, pero no para `CadenaSegura`.
- `std/modelo.syn` y `std/tensor.syn` usan `longitud(tensor)`; el generador
  emitía `longitud(tensor)` como llamada C sin firma. El builtin debe ser
  `Tensor.filas * Tensor.columnas`.
- El smoke POSIX buscaba `<fuente>` pero el fallback del compilador escribe
  `<fuente>.exe` en todas las plataformas.
- Tras aceptar `.exe`, el smoke de `ubuntu-24.04-arm` falló con
  `FileNotFoundError: '_release_smoke_NNN.exe'`: `raiz_proyecto()` devuelve
  `.` y el ejecutable temporal quedaba como ruta relativa; `subprocess` no
  busca en el cwd.

## Cambios

- `compilador/generator/generator.py`: `int64_t longitud(CadenaSegura texto);`
  en el header modular compartido.
- `compilador/generator/emit_expressions.py`: `longitud(tensor)` →
  `((arg).filas * (arg).columnas)`.
- `scripts/verificar_release_limpio.py`: acepta `<fuente>` y `<fuente>.exe` en
  POSIX, limpia ambas y resuelve `cwd` a absoluto antes de ejecutar la salida.
- Plan, expediente y verificación MTS `r332_modular_opensyn`.

## Lección

Una ruta que funciona con `dist` absoluto puede romperse con `dist` relativo:
`Path('.') / nombre` no es ejecutable para `subprocess` sin `./`. El smoke debe
resolver su cwd antes de invocar la salida que acaba de compilar.
