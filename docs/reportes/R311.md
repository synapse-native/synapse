# Reporte R311 — ME r311_workflow_build_canonico

**Commit:** `b6544b1`
**Fecha:** 2026-11-23
**Fase:** Release v8.1.0-industrial — dejar verdes los workflows

## Problema

El job Windows pasó el setup pero moría en el link, con ocho símbolos del
runtime sin definir (`_syn_http_get_archivo`, `_syn_axon_limpiar_toml`,
`_syn_debug_cargar_traza`, `_syn_diagnostic_info`, `_syn_health_check`,
`_syn_lista_agregar`, `_syn_debug_posicion_actual`, `randombytes`).

Causa: el workflow llevaba un comando `gcc` escrito a mano que enumeraba solo
`synapse_rt.c`, `memory.c`, `concurrency.c` y `tweetnacl.c`; el resto del
runtime nunca se compilaba.

## Cambios

`.github/workflows/cross-compile.yml` ejecuta `python build.py` (bootstrap
S1→S2→S3 con el runtime modular de `pipeline.py`) y copia `synapse_stage2.exe`
a `dist/bin/synapse.exe`.

## Lección

Un comando de build duplicado en el workflow es deuda garantizada: cualquier
archivo nuevo del runtime se olvida. El workflow debe llamar al build canónico.
