BLOQUEANTES ENCONTRADOS Y CORREGIDOS:
(1) COMPILADOR INSTALADO NO COMPILABA (bloqueante release): el enlazador nativo
    (ME-R5, `_rt_dir` = dir del exe) invocaba GCC con fuentes relativas al exe
    que el instalador no distribuía (synapse_rt.c/.h, axon/tweetnacl.c,
    vendor/sqlite3/*, nucleo/federated.*, librerias/embedded_libs.h,
    synapse_rt_memory.h). Fix [Files]: todo hermano del exe en bin\.
(2) DESCARGA IA IMPOSIBLE: `MODEL_SHA256_*` = placeholder literal
    "TODO_ACTUALIZAR_AL_COMPILAR" (verificación siempre fallaba);
    `LLAMA_SERVER_SHA256` era el hash del ZIP pero se verificaba el EXE
    extraído (mismatch 100%, abortaba antes de descargar el modelo);
    `MODEL_URL_1B` apuntaba a repo inexistente (TheBloke/deepseek-coder-1.3B-GGUF
    → 401; el real es 1.3b minúscula — y el modo silencioso sin Ollama SIEMPRE
    elige el 1B por VRAM=-1); curl sin --fail guardaba páginas de error HTTP
    (reproducido: 504 de 92 B con exit 0). Fix: hash reales (LFS oid HF = SHA256
    del contenido), hash del exe extraído de b10819 (launcher 9216 B + impl DLL),
    URL corregida, `--fail --connect-timeout 30`. `scripts/update_hashes.ps1`
    reparado (hash del exe extraído, crea su cache dir, oids de modelos vía API HF).
(3) MOTOR IA LOCAL NO ARRANCABA: `ExtractLlamaServerFromZip` copiaba SOLO el
    launcher (9,216 B) y borraba el temporal con sus ~50 DLLs
    (llama-server-impl.dll, ggml*.dll, libomp.dll). Fix: copia completa del ZIP
    (loop FindFirst/FileCopy; DirCopy no existe en Inno Pascal Script).
