# Reporte R320 — ME r320_ld64_dup_flag

**Commit:** `23e023f`
**Fecha:** 2026-11-23
**Fase:** Release v8.1.0-industrial — dejar verdes los workflows

## Problema

Run `45213218955`, job `137827294530` (macos-latest). Compilación y módulos en
verde; el enlace muere:

```
ld: unknown options: --allow-multiple-definition
collect2: error: ld returned 1 exit status
[!] Link modular fallo (rc=1) — intentando unity fallback
ld: unknown options: --allow-multiple-definition
```

`--allow-multiple-definition` es de GNU ld; el linker de Apple no lo conoce y,
como también estaba en el unity fallback, no había segunda oportunidad. El flag
existe porque la compilación modular emite helpers duplicados entre módulos
(`desde_texto` en `_json.c` y `_toml.c`, `contiene` en `_texto.c`/`_reports.c`);
eso se reprodujo localmente al quitar el flag en Windows.

## Cambios

- `pipeline.py`: `_ld_dup_flag` vacío en darwin; `link_align` del enlace de
  caché con el mismo criterio; en darwin se limpia `_module_asts` para enlazar
  en unity (sin definiciones duplicadas).
- `nucleo/principal.syn`: `_dup_flag` con `#ifdef __APPLE__` vacío; la cola de
  enlace usa `%s%s` (`_win_libs`, `_dup_flag`). En win32 el comando es idéntico.
