## Objetivo

Reparar `opensyn/validation_loop.syn`, que no compilaba por usar
`_syn_capturar_comando` (símbolo no declarado) y arrastraba dos variables no
declaradas, y llevarlo a comportamiento E2E verificable con el compilador real:
validación por código de salida, error exacto en el prompt, máximo 3 intentos,
fallo definitivo honesto y feedback humano.

## Cambios

- `opensyn/validation_loop.syn`: `validar_con_check` escribe un temporal único,
  ejecuta `synapse check --no-emit` con `std.sistema.ejecutar_comando`,
  redirige stdout+stderr a un archivo y decide validez por rc.
- `parsear_error_compilacion` extrae `[Synapse] archivo:línea:columna - mensaje`
  y rellena `ErrorCompilacion`.
- `bucle_validacion_detallado` conserva el último código, los errores, los
  intentos y la ubicación del último error; `bucle_validacion` compone el
  mensaje de fallo definitivo. El bucle usa `mientras intentos < MAX_INTENTOS`.
- `guardar_feedback` resuelve `~` con `USERPROFILE`/`HOME` y admite
  `OPENSYN_FEEDBACK_PATH` para pruebas; `registrar_correccion_manual` es el
  punto de entrada de la corrección humana.
- Se corrigió el ownership en los call sites que consumen textos
  (`_syn_strcpy` para `codigo`, `prompt`, `errores`, `ruta_temp` y
  `ruta_salida`; `_syn_strlen` para medir sin transferir).
- `tests/opensyn/test_validation_loop_comportamiento.py`: oráculo E2E nuevo con
  LLM falso y wrapper que invoca el compilador actual.
- `tests/fixtures/compilacion_baseline.txt`: retirado
  `opensyn/validation_loop.syn` (trinquete de Fase 32).
- `docs/plan_ME_r206_validation_loop.md`, `docs/alineacion/r206_validation_loop.md`,
  `docs/verificacion_ME_r206_validation_loop.md` y evidencia
  `auditoria/evidencia/dc81f3f85c2e19f4.json`.

## Lecciones

- El `synapse.exe` instalado (8.1.0) es stale: reporta el módulo como válido
  aunque `main.py` detecta los errores reales. El oráculo usa el compilador
  actual mediante un wrapper y no depende del binario instalado.
- En Windows, `cmd` resuelve el `.exe` local antes que el `.bat` del PATH y
  PATHEXT prefiere `.EXE`; el test fija PATHEXT y ejecuta desde un directorio
  temporal para aislar el wrapper.
- No se usa `_syn_capturar_comando`: no está declarado en `std.sistema` y no
  expone código de salida. La redirección a archivo con `ejecutar_comando`
  permite obtener rc + stdout/stderr sin inventar APIs.
- `guardar_feedback` no debe ejecutarse en cada fallo automático: el manual lo
  define para la corrección manual del usuario.
- El servidor falso debe decodificar el body con `errors="replace"` porque el
  diagnóstico del compilador puede contener bytes no UTF-8 en Windows.
