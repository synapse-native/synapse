# REPORTE R93 — FASE 22: globales mutables en el backend compartido

--- REPORTE DE MICRO-ENTREGABLE ---
TAREA: R93 — Implementar el soporte de **variables globales mutables** a nivel
de módulo en el backend compartido (Manual 3 §3 L74: keyword `variable`),
cerrando el hallazgo H-R92-1 (asignado en R92). El backend S1 no definía
globales mutables (Manual 2 §2 L47-54: solo `constante`); el codegen ya emitía
el C global vía `visitar_declaracion`, pero el **analizador semántico** (Pasada 1,
Manual 2 §8.1 L457) no registraba `DeclaracionVariable` en el scope global —
solo `StmtConstante` — por lo que cualquier referencia a la variable fallaba con
"Variable no declarada".

FASE: 22 (Fundación de Syquex — criterio ROADMAP F22: "El compilador acepta
archivos .syq y genera el mismo AST canónico que Synapse").

MANUAL REFERENCIADO: Manual 2 §2 L47-54 (EBNF módulo: SIN `declaracion_variable`,
solo `declaracion_constante`); Manual 2 §8.1 L457 (Pasada 1: "Estructuras y
Tipos Globales" — registra constantes globales; R93 extiende a variables
globales mutables); Manual 3 §3 L74 (`variable ::= "variable" IDENTIFICADOR
[ ":" tipo ] [ "=" expresion ] NEWLINE`), L122 (`let` SOLO ámbito local).

HASH COMMIT: abf7ad3 (código+tests; docs en commit separado citando este hash).

COMPILACIÓN: frontend SyQuex reconstruido rc=0 anti-stale. Pipeline S1 e2e

DESCRIPCIÓN TÉCNICA:

1. **Defecto raíz**: `AnalizadorSemanticoChecker` (semantic_checker.py) en la
   Pasada 1 (`_verificar` → registro de símbolos globales) iteraba
   `programa.sentencias` y solo manejaba `StmtConstante` (registro como
   `es_constante=True` en el scope global) y `DeclaracionVariable` caía en el
   `else` implícito → NO era registrado → lookup fallía en pasada 3 cuando
   `principal()` referenciaba `INICIO`.

2. **Fix**: nueva rama `elif isinstance(s, DeclaracionVariable)` tras el
   `StmtConstante` en el loop de registro (linea ~317). Registra el símbolo
   con `es_constante=False`, infiere tipo desde `s.tipo` o la expr (igual que
   `StmtConstante` usa `_inferir_tipo`), y detecta REDEFINICION (`ERR_SEM_REDEFINICION`).

3. **Codegen**: sin cambios — `visitar_declaracion` (emit_declarations.py:99)
   ya emitía `int INICIO = 7;` a nivel global (antes del loop de funciones,
   línea generator.py:1268-1276). La emisión era correcta; el bloqueo era
   exclusivamente el semántico.

4. **Verificador formal**: sin cambios — `_verificar_mutaciones_globales()`
   (verificador_formal.py:349) sigue rastreando `AsignacionVariable` (mutaciones)
   no `DeclaracionVariable` (declaraciones). Las mutaciones de globales desde
   funciones siguen marcadas con `ERR_VER_MUTACION_GLOBAL` (E-701) en modo
   `--safe`.

5. **Scope**: la rama nueva es SOLO para `DeclaracionVariable` a nivel módulo
   (producido por el puente desde `NODO_LET` con `vi=1` o `variable` SyQuex).
   No afecta `DeclaracionVariable` locales dentro de funciones (que van por
   `_analizar_funcion` → `_visitar` linea 426). Programas `.syn` nativos NO
   pueden producir `DeclaracionVariable` a nivel módulo (Manual 2 §2 L47-54) →
   el bootstrap S2==S3 es afectado cero (verificado: diff 0 bytes).

RIESGOS IDENTIFICADOS:
  - (i) Inicializadores complejos: para `variable G = f()` (expresión con
    efectos secundarios), el C emitido `int G = f();` ejecuta `f()` en el
    tiempo de carga del runtime, no dentro de `principal()`. Esto es consistente
    con C estándar pero podría sorprender usuario. H-R92-1 menciona
    `_syn_globals_init()` para inicialización pre-`main` — diferido a Fase 23
    (arenas/RC) para inicializadores que requieran runtime complejo. La
    cobertura actual es solo inicializadores constantes (literal/primitivo).
  - (ii) Mutabilidad de globales: en modo `--safe`, mutaciones de globales
    desde funciones ya son detectadas por el verificador formal (E-701). Sin
    `--safe`, los globales son mutables libremente — consistente con H-R91-1
    (semántica por valor aprobada).
