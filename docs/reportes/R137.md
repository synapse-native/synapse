## 1. Evidencia

- `runtime/core/sistema.c:24` — `concat()` cambiado de `malloc()` → `pool_alloc()` con comentario `// cumple Manual 2 §9.1`

- `runtime/core/modelo.c:781` — `_syn_home()` cambiado de `strdup()` → `pool_alloc()` + `memcpy()` (strdup internamente llama malloc, incompatible con pool_free)
- `tests/opensyn/test_inference.py` — limpieza de comentarios obsoletos

### Root cause
Per Manual 2 §9.1: ownership único + RAII estático + prohibido malloc/free en user code.
Per Manual 6 §2.3: `pool_alloc`/`pool_free` es la API del runtime para memoria.

Las funciones que devuelven `CadenaSegura` son propietarias del buffer `datos`. El runtime libera este buffer con `_syn_texto_liberar()` que llama `pool_free()`. Pero `concat()`, `_syn_sha256()`, `_syn_sha256_archivo()` y `_syn_home()` usaban `malloc()` (o `strdup()` que internamente llama `malloc`), lo que causa **undefined behavior** al mezclar dos allocators distintos (`malloc`/`free` vs pool's internally-managed `free`).
