# R115 — Fix Deuda Técnica: std/io.syn + Transpiler int-to-str

**Fecha:** 2026-08-26
**Rama:** feature/fase2-nativa-hm
**Commit código:** `4ffeab4`

## Problema

### 1. std/io.syn violaba la gramática EBNF (Manual 2 §2)

`std/io.syn` línea 13 tenía:
```syq
funcion abrir(ruta: texto, modo: texto = "r") -> Canal:
```

La gramática EBNF del Manual 2 §2 define:
```ebnf
parametro ::= [ "->" ] IDENTIFICADOR ":" tipo
```

**No hay soporte para valores por defecto (`= valor`).** El parser estaba funcionando correctamente al rechazar esto.

### 2. Transpiler no convertía int→str para escribir_linea()

Python `print(42)` funciona porque `print()` acepta cualquier tipo. Syquex `escribir_linea()` solo acepta `texto`. El transpiler generaba `escribir_linea(result)` donde `result` es `entero`, causando error de tipos.

## Solución (conforme al manual)

### Fix 1: std/io.syn
```diff
-funcion abrir(ruta: texto, modo: texto = "r") -> Canal:
+funcion abrir(ruta: texto, modo: texto) -> Canal:
```

Ningún caller dependía del default — todos pasaban `modo` explícitamente.

### Fix 2: Transpiler
- `escribir_linea(x)` → `escribir_linea(entero_a_texto(x))` cuando `x` no es string literal
- Declara `externo funcion entero_a_texto(n: entero) -> texto` cuando se necesita
- Solo envuelve si el argumento no es string ni concatenación
